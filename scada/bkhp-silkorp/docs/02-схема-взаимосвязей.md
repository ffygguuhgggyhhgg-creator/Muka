## 2. Цепочка управления механизмом

Ключевая особенность архитектуры: **кнопка не выдаёт команду в ПЛК напрямую.**
Она только выставляет заявку в тег `StatusStart*`, а выход `RelayOut*`
включает периодический скрипт `ManualStart` — после отработки предпусковой
сигнализации.

```
 Оператор                SCADA-теги                  Скрипты                 ПЛК
────────────────────────────────────────────────────────────────────────────────────
 StartButtonX  ──┐
   (OnClick)     │ проверка: RelayOutX = False
                 │           StatusX = 4 (стоп А)
                 ├─► StatusStartX := 5  ──────┐
                 └─► ManualStartStatus := True │
                                               │
                           ManualStart (периодический, 1 с)
                           ├─ 0…10 с: Alarm16Level, Alarm1Level := True  ──► сирены
                           ├─ >10 с : сирены сняты
                           └─ ≥20 с : если StatusStartX = 5 →
                                        RelayOutX := True  ────────────────► пускатель
                                        StatusStartX := 0
                           └─ ≥120 с: ManualStartStatus := False, таймеры = 0

 StopButtonX   ───► если RelayOutX = True: StatusStartX := 1; RelayOutX := False ──► стоп
   (OnClick)       если StatusStartX = 5 : StatusStartX := 6 (отмена заявки)

                           MnemoControlN/C/T (периодический, 1 с)
   пускатель ──► RelayInX ─┤ (RelayOutX, RelayInX) → StatusX, цвет мнемосхемы
   вход аварии ► RelayAlarmX ┤ 10 с подряд → RelayOutX := False,
                             │              StatusAlarmX := True, AlarmStatus := True
   стоп-кнопка ► RelayStopInX ┤
                           StopButtonsControl (периодический, 1 с)
                             └ если StatusX = 1 и RelayStopInX = False →
                                 RelayOutX := False, StatusStartX := 16

                           TextStatusX_OnDataChange (по изменению StatusX)
                             └ StatusX → текст и цвет надписи на мнемосхеме
```

### Коды тегов механизма

`StatusX` — состояние (вычисляется `MnemoControl*`):

| Код | Условие (`RelayOut`, `RelayIn`) | Текст | Цвет |
|---|---|---|---|
| 1 | 1, 1 | В работе (А) | зелёный |
| 2 | 0, 1 | В работе (М) | жёлтый |
| 3 | 1, 0 дольше 3 с → выход снимается | Стоп (М) | красный |
| 4 | 0, 0 | Стоп (А) | красный |
| 10 | `StatusAlarmX = True` | Авария | красный |

`StatusStartX` — заявка/итог команды:

| Код | Смысл | Кто ставит |
|---|---|---|
| 0 | заявка отработана | `ManualStart` |
| 1 | останов оператором | `StopButton*`, `AlarmDropButton` |
| 5 | заявка на пуск | `StartButton*` |
| 6 | отмена пуска | повторное нажатие пуска, `StopButton*`, авария |
| 16 | останов по потере питания стоповой кнопки | `StopButtonsControl` |

## 3. Конечный автомат задвижки

Один набор силовых выходов на группу (`T6LatchRunOpen`, `T6LatchRunClose`)
и индивидуальный выход выбора (`T6LatchSelectN`), поэтому операции в группе
сериализуются флагом `T6BlockSelectStatus`.

```
 T6OpenButtonN ──► проверки: CalOpenTimeN > 0 (калибровка выполнена)
   (OnClick)                 BlockSelectStatus = False (группа свободна)
                             LatchStatusByteN < 5 (нет аварии)
                       └─► T6OpenStatusN := True; BlockSelectStatus := True

        T6OpenScriptN (периодический, 1 с) — пока OpenStatusN = True:
          OpenTimerN++
          такт 3      : StatusByteN := 1 «в работе», LatchSelectN := True
          такт 6      : LatchRunOpen := True
          концевик LatchOpenN = True → RunOpen := False, StatusByteN := 2 «открыта»,
                                        BlockSelectStatus := False, сброс
          таймаут > 9 + CalOpenTimeN → RunOpen := False, StatusByteN := 5 «авария»,
                                        BlockSelectStatus := False, сброс

        T6CloseScriptN — зеркально, StatusByteN := 3 «закрыта»,
                         таймаут > 9 + CalCloseTimeN → StatusByteN := 5

        T6CalScriptN (калибровка, старт только из состояния «закрыта»):
          CalOpenTimeN := 0; CalCloseTimeN := 0; StatusByteN := 4 «калибровка»
          открывает и считает такты до концевика  → CalOpenTimeN
          закрывает и считает такты до концевика  → CalCloseTimeN
          завершение → StatusByteN := 3, BlockSelectStatus := False
```

`T*LatchStatusByteN` — состояние задвижки: 1 в работе, 2 открыта, 3 закрыта,
4 калибровка, 5 авария.

Отображение задвижек ведут три скрипта на группу:

| Скрипт | Тип запуска | Что делает |
|---|---|---|
| `T*LatchMnemo` | периодический | цвет линий `LineT*Latch*`, `StatusByte` по концевикам, индикатор блокировки |
| `T*LatchStatusBar` | по изменению привязанных тегов | текст состояния каждой задвижки |
| `T*LightControl` | по изменению | лампы «идёт открытие/закрытие»: задвижки 1–5 → лампа `_1`, 6–10 → лампа `_2` |
| `T*CalValueBar` | по изменению | вывод времён калибровки открытия и закрытия |

## 4. Частотные преобразователи

```
 FreqWindow: поле Т1…Т7  ──► T<n>TargerFreq (Гц, Single)
                                │ T<n>FreqTarget (по изменению T<n>TargerFreq)
                                └─► T<n>FreqToPLC := TargerFreq * 10000 / 50  ──► ПЛК
 T1toT7StartFreq (при запуске проекта): FreqToPLC := 4400, TargerFreq := 22 Гц
 Телеметрия из ПЛК: T<n>Freq (Гц), T<n>Power (А) — выводятся полями экрана
```

Масштаб `×10000/50` означает формат ПЛК 0…10000 на 0…50 Гц.

## 5. Весовой терминал

```
 Кнопки экрана ──► L1_D1_Cmd:  0 чтение · 1 запись · 2 в работу · 3 стоп цикла · 4 проход
 Из терминала:  L1_D1_Weight (вес), L1_D1_S_Start/Stop/Dose/Pause/Load/UnLoad/Error,
                L1_D1_C_C (счётчик весов), L1_D1_C_E (счётчик отпуска), L1_D1_C_n/d/P/t,
                L1_D1_Par_* (параметры дозирования), L1_D1_D_In1/2, D_Out1/2
 Indicators (периодический)          → лампы Start/Stop/Pause/Error, состояние заслонок
 Prod (периодический)                → Capacity = производительность, т/ч
 ErrorCapacitControl (периодический) → аларм «слишком высокая подача» при Capacity > 34
 CalculateLocalCounter (периодический)→ LocalCounter — локальный счётчик отпуска
 VesRepValueButton / VesRepIntervalButton → отчёты Stimulsoft
```

## 6. Сигнализация и блокировки

```
 AlarmStatus (общий признак аварии)
   ставится MnemoControlN/MnemoControlT при удержании RelayAlarm* 10 с
        └─► Alarm (периодический): мигание AlarmBox и сирен по тактам 1,2,4,6,8,10,
                                    затем AlarmStatus := False

 Alarm16Level, Alarm1Level ──► дискретные выходы сирен (16-й и 1-й этаж)
   пишут: ManualStart (предпуск), Alarm (авария), AlarmTest (проверка)

 BlockControl ──► BlockControlMnemo (индикатор), T4BlockControl (защита маршрутов)
 AlarmStopButton ──► групповой аварийный останов всех механизмов
 AlarmDropButton ──► сброс аварий механизмов
```

## 8. Матрица доведённости по механизмам

`Status` — тег состояния, `ПЛК` — привязка выходов к контроллеру,
`Кнопка` — объект на мнемосхеме, `Обработчик` — скрипт, реально привязанный
к этой кнопке по имени.

| Мех. | Заводская позиция | Status | Выход→ПЛК | Кнопка пуска | Обработчик привязан | Текст статуса |
|---|---|---|---|---|---|---|
| N1…N6 | Нория 1…6 | да | да | да | да | да |
| N7 | Нория 1а | да | **нет** | `StartButtonN7` | **нет** (скрипт `…N1a`) | да |
| N8 | Нория 2а | да | **нет** | `StartButtonN8` | **нет** (скрипт `…N2a`) | да |
| N9 | Нория 11 | да | **нет** | `StartButtonN9` | **нет** (скрипт `…N11`) | да |
| N10 | резерв | да | нет | нет | — | нет |
| C1…C4, C7…C12 | Аспирация 1…4, 7…12 | да | **нет** | да | да | да |
| C5 | Аспирация 1а | да | **нет** | `StartButtonC5` | **нет** (скрипт `…C1a`) | да |
| C6 | Аспирация 2а | да | **нет** | `StartButtonC6` | **нет** (скрипт `…C2a`) | да |
| C13, C14 | резерв | да | нет | нет | — | нет |
| T1…T7 | Транспортёр 1…7 | да | да | да | да | да |
| T8…T11 | Транспортёр 8…11 | да | **нет** | да | да | да |
| T12 | Транспортёр 8а | да | **нет** | `…ButtonT12` | **нет** (скрипт `…T8a`) | да |
| T13 | Транспортёр 17 | да | **нет** | `…ButtonT17` (не T13) | да, но к «чужому» объекту | да |
| T14 | Транспортёр 9а | да | **нет** | `…ButtonT14` | **нет** (скрипт `…T9a`) | да |
| T15 | Транспортёр 17а | да | **нет** | `…ButtonT15` | **нет** (скрипт `…T17a`) | да |
| T16 | Транспортёр 25 | да | **нет** | `…ButtonT16` | **нет** (скрипт `…T25`) | да |
| T17 | Транспортёр 24 | да | **нет** | `…ButtonT13` свободна* | **нет** (скрипт `…T24`) | да |
| T18 | Транспортёр 22 | да | **нет** | `…ButtonT18` | **нет** (скрипт `…T22`) | да |
| T19, T20 | резерв | да | нет | нет | — | нет |

\* На мнемосхеме есть объекты `…ButtonT1…T18` по всем трём действиям
(прямой, реверс, стоп). У 12 из 18 номер объекта совпадает с индексом тега,
а пара T13/T17 перекрещена: объект `…ButtonT17` управляет тегами `T13`,
а объект `…ButtonT13` не привязан ни к чему, при том что осиротевший скрипт
`…ButtonT24_OnClick` управляет тегами `T17`. См. дефект D-02.
